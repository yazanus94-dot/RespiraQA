# Dataset Documentation

## ICBHI 2017 Respiratory Sound Database

- **Official challenge site:** https://bhichallenge.med.auth.gr/
- **Research paper:** https://eden.dei.uc.pt/~ruipedro/publications/Conferences/ICBHI2017a.pdf

The database contains respiratory recordings and annotation files. Each
annotation row records four values:

| Column | Meaning |
|---|---|
| 1 | Respiratory-cycle start time in seconds |
| 2 | Respiratory-cycle end time in seconds |
| 3 | Crackle indicator (0 or 1) |
| 4 | Wheeze indicator (0 or 1) |

Four cycle labels:

| Crackle | Wheeze | RespiraQA class |
|---:|---:|---|
| 0 | 0 | `normal` |
| 1 | 0 | `crackles` |
| 0 | 1 | `wheezes` |
| 1 | 1 | `both` |

The labels annotate sounds, not diseases.

## Expected local layout

The project makes dataset paths configurable (`config/config.yaml`); it
does not hard-code archive extraction locations. The recommended layout:

```text
data/raw/ICBHI2017/
├── audio/          # *.wav recordings
├── annotations/    # *.txt annotation files (same basename as audio)
└── metadata/       # optional release metadata
```

Recordings are matched with annotations by file basename. Patient IDs are
inferred from the ICBHI naming convention (leading digits of the
recording name).

## Official patient-independent split

The challenge publishes an official patient-independent training/testing
partition. Provide it as a split file (`patient_id<TAB>partition` lines)
via `dataset.split_file` in the configuration. The pipeline verifies that
no patient occurs in more than one partition and refuses to proceed if
leakage is detected. Validation splits, when needed, are created only
from training patients.

## Derived data (never committed)

- `data/interim/manifest.csv` — one row per recording.
- `data/interim/cycles.csv` — one row per valid annotated cycle.
- `data/processed/features.csv` — acoustic feature table.
All three are generated by the pipeline scripts and are excluded via
`.gitignore`.

## Synthetic fixture

`tests/fixtures/synthetic/` contains a small, fully synthetic,
deterministic dataset (no real patient data) committed for tests and for
the synthetic demo pipeline (`config/config.synthetic.yaml`). It is
regenerable via `python tests/generate_fixtures.py`.
